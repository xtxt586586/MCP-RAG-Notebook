# 检索对照冒烟记录

本记录是一次可复现的功能与性能冒烟测试，不代表真实业务效果。数据由三篇虚构文档和随文档编写的 30 条问题组成，标注粒度为文档，未经过独立人工审核。每篇文档在本次索引中仅有一个切片，不能用于评价复杂长文档或跨文档检索。

2026-11-21，在单机 Docker 隔离环境中使用本地缓存的 BGE-M3 和 BGE reranker，模型预热后顺序执行，K=1，重排候选数上限为 6。耗时包含单次问题向量化和检索，重排方案还包含重排序；不包含模型冷启动、文档索引及最终回答生成。

| 方案 | 文档 Recall@1 | MRR@1 | 单问题中位耗时 |
| --- | ---: | ---: | ---: |
| 稠密向量检索 | 0.967 | 0.967 | 473 ms |
| 混合检索 | 0.967 | 0.967 | 476 ms |
| 混合检索 + 重排 | 1.000 | 1.000 | 6417 ms |

重排在这组样例中多命中 1 条，但中位耗时明显增加；样本过小且问题与资料共同编写，不能推断其在真实任务中一定有效。实际使用前需要独立核对真实问题和相关片段，扩大文档数量、测试不同 K，并分别记录冷启动与端到端延迟。默认示例配置关闭重排，可根据质量和延迟需求选择启用。

复现方法见项目 README 的检索评测部分。模型、硬件、负载和文档切分变化都会影响结果。以上检索指标不衡量回答引用正确性或无依据问题拒答率。

## 问答抽样检查

另在相同隔离环境中，使用“仅知识库”模式做了 6 条人工核对的问答抽样：3 条有依据的问题分别询问图书借阅规则、商城免运费门槛和工作坊迟到规则；3 条无依据的问题分别询问图书馆管理员工资、商城客服电话号码和工作坊报名费。一次运行中，3 条有依据问题均给出了与资料一致的回答，并在正文引用了对应文档；3 条无依据问题均表示资料不足。

这只是一次极小规模的人工抽查，不是稳定性或拒答率的正式评测。检索接口仍会返回其他不相关候选文档，回答生成依赖外部模型，其结果也可能随时间变化；需要独立标注的更多问题、重复运行与逐条核验引用，才能评估实际可靠性。问答延迟包含检索和外部模型调用，不与上面的检索延迟直接比较。

## 空缓存模型准备检查

2026-11-21 在一个全新的 Docker 命名卷中下载 BAAI/bge-m3（未挂载已有 Hugging Face 缓存），下载完成后关闭网络访问，从该卷加载模型并编码测试文本成功，输出向量维度为 1024。下载容器显式配置了本机可访问的 HTTP/HTTPS 代理；如果部署机器访问 Hugging Face 权重分发域名受限，仍需要先配置有效代理或自行准备模型缓存。此项只验证 Embedding 模型，不表示 Reranker、其他外部服务或全新主机的整个 Docker Compose 已无条件开箱可用。
