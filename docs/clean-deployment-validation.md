已完成的后端镜像构建中，依赖安装层约耗时 432 秒，镜像导出约 152 秒；实际时间受网络、机器和缓存影响。另一次隔离栈问答复测使用先前准备好的 BGE-M3 模型目录，文档重新上传并建立索引；每题的来源、回答和耗时见 [真实模型报告](../eval/report.md)。该结果不能证明空缓存在线模型下载已经完成。

另有 2026-11-21 的独立模型准备检查：在全新 Docker 卷中下载 BGE-M3 后，断网加载并输出 1024 维向量，见[检索冒烟记录](retrieval-smoke-report.md)。该项只证明模型准备，不等同于本次完整 Compose 从空缓存启动成功。

构建和模型准备期间观察到的问题：Docker Hub 的固定 MinIO 标签不能稳定拉取；Hugging Face 的 Xet 权重下载曾停在 0 字节，禁用 Xet 后普通 HTTPS 下载开始增长；网络代理偶有 EOF、502 和超时；重复启动同一 Compose 项目会造成容器创建冲突。脚本现预先检查模型，MinIO 支持固定源码构建后备方案，并允许配置构建代理。

本次空缓存在线准备在 1786.9 秒后手动中止，权重仅下载约 240 MiB，不能视为通过。随后将预先取得的完整 BGE-M3 放到 README 指定目录，权重 SHA-256 与 Hugging Face 的文件标识 `b5e0ce3470abf5ef3831aa1bd5553b486803e83251590ab7ff35a117cf6aad38` 一致；按 README 设置离线模型路径后执行 `bash scripts/setup.sh`，完成离线向量化、服务启动、索引和三条真实问答，耗时 134.1 秒、退出码 0。这次使用了现有 Docker 镜像与此前创建的隔离数据卷，不能当作全新主机首次在线部署的耗时。
